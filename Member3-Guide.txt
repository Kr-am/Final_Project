[ ] Use LogNext (0..49) for current record insertion slot.
[ ] Store type, source account ID, destination ID, amount, resulting
    source/current balance, status, and error code in parallel arrays.
[ ] Ensure every DW log field uses slot*2 byte offset; DB fields slot.
[ ] If LogCount<50, increase count; otherwise keep count exactly 50.
[ ] After writing, increase LogNext and wrap from 49 back to 0.
[ ] Do not read or write outside any of the 50-element arrays.
[ ] Keep separate status for rejected attempts instead of treating an

[ ] Do not change bank balances during logging.

Implement ShowHistory:

[ ] Display in chronological order: if LogCount<50 start at slot 0;
    if LogCount=50 start at LogNext (the oldest slot).

    message when empty.

RING-BUFFER PSEUDOCODE
  slot = LogNext
  LogType[slot] = TxnType
  LogSrc[slot] = TxnSourceID
  LogDst[slot] = TxnDestID
  LogAmount[slot] = RequestedAmount
  LogBalance[slot] = TxnResultBalance
  LogStatus[slot] = TxnStatus
  LogError[slot] = TxnError
  if LogCount < 50: LogCount++
  LogNext = (LogNext + 1) modulo 50

WORK PACKAGE C - SUSPICIOUS WITHDRAWAL DETECTION (HOUR 2-4)
Implement UpdateFraudAfterSuccess. Only call it after a fully successful
D/W/T; rejected attempts must not affect its counters.
[ ] Maintain a FraudStreak byte for each of 10 accounts.
[ ] For a successful withdrawal greater than 10,000 centavos, add 1
    to the currently logged-in source account's streak.
[ ] At exactly 10,000 centavos, treat as NOT above threshold; reset.
[ ] For a successful withdrawal <=10,000, reset that account's streak.
[ ] On successful deposit, reset receiving account's streak.
[ ] On successful transfer, reset the streak for BOTH source and target.
[ ] When streak changes from 2 to 3, set that account's FraudFlags=1,
    increase FraudAlertCount, and print a clearly marked fraud warning.
[ ] Streak 4 or greater should not repeatedly count the same alert.
[ ] Ensure index refers to account position (0..9), not bank ID (1001+).
[ ] Do not reject a valid withdrawal merely because it looks suspicious.
[ ] Keep the flag visible in account summaries for the session.

FRAUD PSEUDOCODE
  IF TxnStatus != 1: RETURN
  IF TxnType == 'W':
     IF RequestedAmount > 10000:
        streak[current account]++
        IF streak just became 3:
           flag[current account] = 1
           FraudAlertCount++
           print warning
     ELSE streak[current account] = 0
  ELSE IF TxnType == 'D': streak[current account] = 0
  ELSE IF TxnType == 'T':
     streak[source account] = 0
     streak[destination account] = 0
  RETURN

If an account already has a flag, keeping its flag = 1 is intentional.
The indicator means 'rule triggered during this session', not 'fraud proven'.
